# Release installation and recovery — pose vs infrastructure

**Pose bundle:** a flat-root incremental release updates scripts/docs if listed, stages five data-only modules in `incoming/` and installs a batch plan. `python install-update.py --library "<LIBRARY>"` preflights, then `--apply` stages files and creates rollback receipts. Existing `.blend`, original source CSV, SQLite tracker, pose revisions and approval history are preserved. Numeric geometry tests and editorial source flags are **not** install gates; only file-integrity, source/template fingerprint and safe-path requirements protect the library.

**Infrastructure bundle (infra 0001):** a different flat-root ZIP contains `updates/` payload mapped into canonical docs and `scripts/`. Its `UPDATE-MANIFEST.json` schema 2 has only named allowed docs/script targets and SHA-256 hashes, and its own `install-update.py` implements dry-run/apply/rollback with `history/update-backups/.../INSTALL-RECEIPT.json`. Install it outside the live library root. A tooling-only update does not create a Blender revision, advance a pass, change rig geometry or accept any pose. Backup the old files before replacement.

**Generated reports:** one batch attempt records all five results under `snapshots/` and refreshes `review/` + `upload/`. The single combined feedback ZIP embeds the portable context; a separate handoff ZIP is a compatibility/exception path, not required for normal review. Original PNGs in `review/`/`upload/` and the single ZIP can be recreated from authoritative revision previews with `python scripts/refresh_exchange.py` without Blender. Do not delete snapshots or pose revisions while cleaning disposable folders.

**Rollback:** the infrastructure installer `--rollback "<RECEIPT>"` verifies that installed target hashes have not changed since apply; it refuses to overwrite subsequent user modifications. Previous files remain under timestamped backups. If Blender geometry is poor, **do not** roll back the whole library: retain the revision as `needs_work`, evaluate other four, and optionally author a new pose module for another pass.

**Tests:** an offline installation/feedback test verifies file operations and evidence generation, not the 3D physical correctness of generated geometry. A local Blender render is authoritative for visual assessment. Never conflate ZIP, rig support proxies or offline dry-run with pose approval.
